# Stage 5.1 technical report — adaptive curved lining mesh

## 1. Scope

Stage 5.1 addresses one specific defect revealed by a real Blender smoke test: the Stage-1 eight-corner analytical segment was being used directly as the Stage-5 renderer/sensor mesh, producing a visibly polygonal six-segment opening.

No published Tunnel Scanner equation is changed in this stage. The correction is architectural: **analytical/control geometry is separated from render/sensor discretization**.

## 2. Root cause

The Stage-1 segment has four inner/outer corner pairs (eight vertices total). Its intrados and extrados are planar quads between angular boundaries. This is faithful to the paper's coarse hexahedral description but geometrically unsuitable for a circular tunnel if a segment spans roughly 65–75 degrees.

For a circle of radius `R`, the maximum radial deviation of one chord spanning angle `delta` is

```text
s = R * (1 - cos(delta/2))
```

For canonical seed 5812 at `R = 3.35 m`, the old representation gives approximately:

- K: 53.4 mm;
- A blocks: 550.1 mm;
- B blocks: 614.3 mm.

This explains the Blender screenshot without invoking camera or shading artifacts.

## 3. Representation split

The eight-corner `SegmentMesh` is retained unchanged and remains authoritative for:

- front/back angular boundaries;
- ring closure constraints;
- Stage-3 rigid transforms;
- displacement-joint boundary corners;
- reconstruction traceability.

A new `CurvedSegmentMesh` is derived from it only for rendering/sensor intersection.

This avoids feeding tessellation density back into structural mathematics.

## 4. Surface parameterization

For normalized circumferential coordinate `u` and longitudinal coordinate `v`:

```text
start(v) = lerp(front_start, back_start, v)
end(v)   = lerp(front_end,   back_end,   v)
alpha(u,v) = lerp(start(v), end(v), u)
y(v) = -L/2 + v*L
```

For each radius `rho in {r,R}`:

```text
x = rho * sin(alpha)
z = rho * cos(alpha)
```

Thus **every generated intrados/extrados vertex lies exactly on its nominal cylinder**. Front/back taper changes the angular coordinate but not the radius.

The four analytical corner locations are exact grid corners, preserving the Stage-1 boundary conditions.

## 5. Conservative tessellation criterion

Requested default geometric tolerance:

```text
epsilon = 0.002 m
```

The chord angle corresponding to that sagitta at the outer radius is

```text
delta_max = 2*acos(1 - epsilon/R)
```

Two angular variations occur inside a segment:

```text
U = max(abs(front_span), abs(back_span))
V = max(abs(back_start-front_start), abs(back_end-front_end))
```

`V` captures the maximum angular twist generated by different front/back boundaries. Since this difference is linear in `u`, its maximum is attained at a boundary.

For a grid cell, the largest angular separation across a possible triangulation diagonal is conservatively bounded by

```text
delta_cell <= U/Nu + V/Nv
```

The implementation searches for the lowest-cell-count `(Nu,Nv)` satisfying

```text
U/Nu + V/Nv <= delta_max
```

under configured subdivision bounds.

## 7. Deformed surfaces

Stage 3 already derives one rigid XZ transform per physical segment. Stage 5.1 first builds the curved segment in its nominal local frame, then applies the same rigid transform to every curved vertex.

Across the 1,000-ring deformation stress test, the maximum measured radius error was approximately `1.33e-15 m`.

## 8. Circumferential outer collars

The Stage-4 provisional circumferential joint reconstruction is an outer collar split into six segment-shaped pieces. Stage 5.1 now derives a curved annular-prism surface for those collar pieces using the same sagitta policy.

Narrow prescribed radial joints remain Stage-4 hexahedra. Stage-3 displacement joints also remain exact boundary bridges.

## 9. Scene-package changes

`build_nominal_scene_package()` and `build_deformed_scene_package()` now accept:

```python
surface_meshing=SurfaceMeshingConfig(max_sagitta_m=0.002)
```

The default uses 2 mm.

Lining objects expose additional scalar metadata:

```text
analyticalSource
surfaceToleranceM
surfaceAchievedMaxSagittaM
surfaceSubdivisions
surfaceLongitudinalSubdivisions
```

## 11. Blender status

The Blender adapter receives the tessellated vertices/faces from the scene JSON and uses `Mesh.from_pydata`.

A Blender executable is not available in the current execution environment, so the new geometry still requires the external runtime smoke test documented in `BLENDER_SMOKE_TEST.md`.

## 12. Remaining scope before bolt pockets

Stage 5.1 resolves the coarse lining surface issue. It does not yet add bolt pockets / bolt heads, Blender Boolean operations, sensor-facing nominal intrados groove interpretation, material/reflectance physics, or multiple-ring longitudinal tunnel assembly.
